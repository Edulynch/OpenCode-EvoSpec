# Feature 002 MVP Workflow Tasks

Implementation is test first and serial by dependency: Core domain/schema work precedes persistence/codec/reload, which precedes CoreService validation and mutation, which precedes WorkflowService, optional CLI, quality, and finally `T019`. In task order, `T001 -> T002 -> T003 -> T004 -> T005 -> T006` establishes Core; serialized `T006` completes the persisted review contract before `T014`. After Core, non-overlapping policy work in `T007` through `T009` may proceed. Core tasks are not parallel, and `T008`/`T009` or `T011` through `T016` are not parallel when they share files or contracts. `T010` then precedes `T011` through `T016`; optional `T017` follows a stable facade; `T018 -> T019` is final. This dependency order explicitly upholds Core domain/schema -> persistence/codec/reload -> CoreService validation/mutation -> WorkflowService -> optional CLI -> quality -> `T019`.

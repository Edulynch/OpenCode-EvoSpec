# EvoSpec source-development specifications

These specifications describe the evolution of **EvoSpec itself**, not Feature/Slice records for an application consuming EvoSpec.

- Keep each existing numbered feature's `spec.md`, `plan.md` and `tasks.md` together; preserve existing feature numbering and history.
- Use specs for intended behavior, implementation plans and engineering tasks. Link decisions and scope changes to the relevant documents rather than duplicating them.
- Never treat a source-development spec as a Core-accepted agreement, criterion receipt, completed Feature or published Living Spec.
- Separate aspirations from implemented and tested behavior; do not silently rewrite old approvals when a later proposal changes direction.
- New source specs should follow the repository's existing specification convention and explicit owner decisions.

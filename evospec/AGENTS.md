# Python implementation ownership

This directory contains EvoSpec's implementation, **not** a consumer project's working records. Inherit the repository-root `AGENTS.md`.

- Put domain identities, types and state validation in `domain.py`; phase and transition logic in `lifecycle.py`; application orchestration in `workflow.py` and `services.py`.
- Put serialization, atomic writes, revision checks and read/recovery behavior in `persistence.py`. Do not create an alternate state store or bypass that layer with direct writes.
- Put provider-neutral agent contracts in `agent.py`, `agent_protocol.py` and the protocol schema; put CLI and OpenCode integration only in their corresponding adapters.
- Preserve accepted agreement and receipt identity, immutable history, exact schema contracts, expected revisions, explicit permissions and the difference between evidence, acceptance and publication.
- When introducing durable data, decide its canonical model/serializer/reader, schema and migration/compatibility boundary first. Add negative tests for stale revisions, wrong roots and unauthorized transitions.
- Never treat text generated by an agent as a human-accepted decision. Never let a workflow helper publish Product Truth, mark verification PASS or authorize release on its own.
- Packaged provider/UX assets belong in `resources/`, not alongside state modules. Read `docs/architecture.md` for the implemented boundary.

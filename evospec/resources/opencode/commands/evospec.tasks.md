With no task details, call `evospec_continuity` with `operation: "tasks"` as a read-only projection. To add work through Core, use the current revision and stable criterion, Increment, dependency, and (when active) exact mandate IDs; a mandated Task must stay within the bound Feature scope. Human edits to `tasks.md` are definitions only after explicit `reconcile`; preserve stable IDs, relation/dependency history, use typed `T-new-name` aliases and explicit references when adding, and provide the exact `retire_ids` set when removing. A reconcile under a mandate must name its exact ID. Changes to bound criteria or Increments stale that mandate; they do not expand it. To record a reasoned `BLOCKED`, `CANCELED`, or `REOPENED` Task event, use `operation: "tasks"` with the same Task ID, exact mandate ID, `task_event`, `reason`, and `evidence_ref`; reconcile unresolved effects before changing Task status. Cancellation is not success. Reopen a blocked, canceled, reported, or completed Task without changing its ID; begin a new attempt and record a fresh linked check before it can complete again. Core rejects invalid dependencies/cycles and stale revisions. Generated checkboxes are projections; editing them never records progress. Legacy projects remain on their existing workflow.

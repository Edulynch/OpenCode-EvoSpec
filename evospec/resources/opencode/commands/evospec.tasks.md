With no task details, call `evospec_continuity` with `operation: "tasks"` as a read-only projection. To add work through Core, use the current revision and stable criterion, Increment, dependency, and selected Feature's exact mandate ID; mandates are Feature-local and IDs cannot be reused across Features. A mandated Task must stay within that Feature's bound criterion and Increment IDs. Human edits to `tasks.md` are definitions only after explicit `reconcile`; preserve stable IDs, relation/dependency history, use typed `T-new-name` aliases and explicit references when adding, and provide the exact `retire_ids` set when removing. A reconcile under a mandate must name that Feature's exact ID, and cannot run while any Task checkpoint is unresolved. A changed normative Feature Outcome, criterion definition, or Increment Outcome stales the mandate even if IDs remain unchanged; explicitly reconcile, then replace by naming its exact old ID. Title, notes, formatting, and technical plan refinements do not stale it; a plan refinement may reference a bound Increment but cannot expand normative scope. To record a reasoned `BLOCKED`, `CANCELED`, or `REOPENED` Task event, use `operation: "tasks"` with the same Task ID, exact mandate ID, `task_event`, `reason`, and `evidence_ref`; reconcile unresolved effects before changing Task status. Cancellation is not success. Reopen a blocked, canceled, reported, or completed Task without changing its ID; begin a new attempt and record a fresh linked check before it can complete again. Core rejects invalid dependencies/cycles and stale revisions. Generated checkboxes are projections; editing them never records progress. Legacy projects remain on their existing workflow.
